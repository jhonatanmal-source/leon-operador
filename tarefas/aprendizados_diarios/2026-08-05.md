- ## Correção: safe_copy_rates_from_pos numpy (mt5_safe.py)

### Erro
- `mt5_safe.safe_copy_rates_from_pos` acessava campos por atributo (`r.time`, `r.open`), mas `mt5linux_compat.copy_rates_from_pos` retorna `numpy.ndarray` de `numpy.void` → `'numpy.void' object has no attribute 'time'`.
- Impacto: backtest MCP retornava `candles_analyzed: 0` mesmo com MT5 disponível; health checks de candles e OHLC do market MCP quebravam silenciosamente.

### Correcao
- `mt5_safe.py` `safe_copy_rates_from_pos`: helper `_field(row, name)` que tenta acesso por chave (`row[name]`) com fallback para atributo (`getattr`). Campos convertidos para float/int explícitos.
- `symbol_info_tick` e `symbol_info` NÃO têm o bug (retornam netref rpyc com atributos) — verificado com dados reais.

### Resultado
- 50 candles M15 reais retornados corretamente; backtest MCP agora obtém 1440 candles (antes 0); símbolo inválido retorna dict de erro sem exceção.
- 356 testes passando (zero regressão).
- Consumidores candle_reader.py (acesso por chave) e mt5_candles.py (pd.DataFrame) já funcionavam — a correção era necessária apenas na função wrapper dos MCPs.

### Padrao
- Verificador: ao consumir retorno de `copy_rates_from_pos`, SEMPRE usar acesso por chave (`r["time"]`) ou helper robusto; nunca por atributo (`r.time`), pois o retorno é numpy, não namedtuple.
- Bug detectado durante validação de backtest real — reafirma: validar engines com dados reais, não apenas simulação.
