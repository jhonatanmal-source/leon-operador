- ## MISSION-20260805-CORRECAO-TP — Cadeia do TP técnico

### Operação
Implementação autorizada da correção da cadeia do TP técnico em shadow trades.

### Decisões
- **S1**: `src/shadow_trade.py` não usa mais fallback `entry + risk*2`. Sem `levels["tp2"]` → `NO_TECHNICAL_TP` (paridade com `entry_price_engine` que já bloqueia com levels None).

### Erros encontrados
- **SyntaxError com ternário em comprehension filter**: `[t for t in xs if (t > tp1) if dir == "COMPRA" else (t < tp1)]` é inválido — `comp_if` não aceita expressões condicionais sem parênteses. Correção: envolver o ternário em parênteses `if ((t > tp1) if dir == "COMPRA" else (t < tp1))`.

### Correções aplicadas
- `src/smc_price_levels.py`: M1 (referência de zona usa entry quando fornecido), M2 (garante tp1 != tp2), M3 (cap `MAX_TECHNICAL_RR = 8.0`), M4 (FVG opera só sobre candles fechados).
- `src/shadow_trade.py`: S1 (sem fallback risk*2), S2 (guard `UNREALISTIC_ENTRY_PRICE` >30% da mediana), S3 (rotulação RR real).
- `src/teste_shadow_trade_learning.py`: precisou de mock de `build_smc_trade_levels` + inserção do project root em sys.path (o patch `src.*` não resolve quando o script roda de `src/`).

### Padrões identificados
- Testes sintéticos para `build_smc_trade_levels` exigem série com FVG no início + rally sobreposto (sem novos gaps) + 2 swings acima do entry — validar via execução antes de escrever o teste.

- `backups/` contém diretórios com nomes de teste duplicados que o pytest tenta coletar — rodar `pytest tests/` explicitamente.
