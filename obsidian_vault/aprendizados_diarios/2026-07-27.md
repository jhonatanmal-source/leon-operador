- ## Remoção do limite de 3 trades/dia para modo demo/estudo

**Data:** 2026-07-27
**Categoria:** decisao

### Contexto
Operando em demo com `scope = demo_execution` e `demo_only = true`, o limite de 3 trades/dia restringia a coleta de aprendizado. Com o gerenciamento de perda diária (`daily_loss_percent = 2.0%`) ativo, é seguro remover o limite quantitativo e deixar a perda máxima diária como proteção.

### Alterações
- `config.ini [EXECUTION] max_demo_orders_day`: 3 → **0** (0 = sem limite)
- `config.ini [RISK] max_trades_day`: 3 → **0** (consistência visual)
- `leon_config.py MAX_TRADES_DAY`: 3 → **0** (consistência, constante não usada para gating)

### Guards que permanecem ativos
- ✅ Conta real bloqueada (`demo_only = true`)
- ✅ Daily loss guard (2.0%)
- ✅ News shield (bloqueia em notícias de alto impacto)
- ✅ Max spread
- ✅ Structural gate (zone validation)
- ✅ Autonomy scope
- ✅ Nenhuma ordem é enviada ao MT5 real

### Mecanismo de segurança
O código em `mt5_order_executor.py` linha 839 verifica:
```python
if config["max_demo_orders_day"] > 0 and ordens_hoje >= config["max_demo_orders_day"]:
    return _bloqueio(...)
```
Com `max_demo_orders_day = 0`, a condição `> 0` falha e o limite é desabilitado. Para reativar, basta voltar para qualquer valor > 0.

### Testes
- 19/19 testes em `test_mt5_order_executor.py` passaram
- 49/49 testes em `test_risk_control_agent.py` passaram

- ## Ciclo de aprendizado fechado — Lab Entry Policy + Bootstrap Winrate

**Data:** 2026-07-27
**Categoria:** correcao

### Problema
O LEON não estava aprendendo com os erros porque:
1. `lab_entry_policy.py` não incluía `TOP_DOWN_H4_H1_M15` em `ALLOWED_MISSING_CONFIRMATIONS`, fazendo com que **nenhuma shadow trade** fosse elegível para evidência (0 de 19)
2. O bootstrap (`leon.py` linha 673) criava entradas simuladas incondicionalmente, sem verificar winrate recente

### Correções
**Arquivo: `src/lab_entry_policy.py`**
- Adicionado `"TOP_DOWN_H4_H1_M15"` ao set `ALLOWED_MISSING_CONFIRMATIONS`
- Resultado: de 0 → **15 shadows elegíveis** para evidência (5W/10L, 33.33%)

**Arquivo: `src/learning_bootstrap.py`**
- Criada função `_winrate_shadows_recentes(ultimas_n=20)` — calcula winrate das últimas N shadows
- Criada função `auto_simulate_permitido(brain_score, winrate_min)` — avalia se pode simular
- Adicionado `auto_simulate_min_winrate = 30.0` aos limiares

**Arquivo: `config.ini`**
- Adicionado `auto_simulate_min_winrate = 30`

**Arquivo: `src/leon.py`**
- Condição de bootstrap agora usa `auto_simulate_permitido()` em vez de apenas `brain_score >= min_score`
- Bootstrap bloqueia se winrate das últimas 20 shadows < 30%

### Resultado
- Com winrate atual de 27.8%, **bootstrap não cria mais entradas**
- Lab Entry Policy começa a acumular evidência real (15 trades elegíveis)
- Para destravar: winrate precisa subir acima de 30% (configurável em `config.ini [BOOTSTRAP] auto_simulate_min_winrate`)
